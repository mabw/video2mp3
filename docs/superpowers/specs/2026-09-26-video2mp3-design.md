# 视频管家 设计文档（spec）

日期：2026-09-26
状态：待用户审阅
来源：对 `docs/idea.md` 的技术评审与修正，经需求澄清后定稿

## 1. 背景与目标

老人在手机上收到/刷到视频（微信转发、抖音），希望转成 MP3 存进 U 盘，插到唱戏机/小音箱上听。本软件运行在老人的 Windows 电脑上，**由老人自己日常操作**，实现：

- 视频（微信另存/拖拽）与抖音链接统一入口；
- 自动转 MP3（UUID 命名），本地保留原视频与 MP3 及映射关系；
- 支持在电脑上播放原视频与 MP3（调用系统默认播放器）；
- MP3 先留本地，按需发送到 U 盘根目录；
- 插上 U 盘后可查看盘内歌曲并删除。

非目标（backlog，第一版不做）：内嵌播放器、手动改标题、语音播报、开机自启、多 U 盘批量管理、视频剪辑。

## 2. 关键决策

| 决策 | 结论 | 依据 |
|---|---|---|
| 运行平台 | Windows（开发机为 macOS） | 老人电脑为 Windows |
| 操作者 | 老人自己 | 界面极简、每步强反馈、高容错 |
| 播放设备 | 唱戏机/小音箱 | 决定编码参数与文件名规则 |
| MP3 规格 | 44.1kHz / 立体声 / CBR 128kbps / 无 ID3 标签 | 实测已验证可播样本 `一襟风月.mp3`（VLC 默认档转换）与此规格一致 |
| U 盘写入位置 | 根目录 `\<uuid>.mp3` | 多数唱戏机不递归子目录；UUID 短 ASCII 文件名兼容性最优 |
| 命名 | 文件用 UUID，界面显示标题 | "UUID 给机器、标题给人"，同名视频不冲突 |
| 抖音下载 | yt-dlp 子进程调用 | Douyin_TikTok_Download_API 属服务端项目，对单机自用过重 |
| FFmpeg | 子进程调用，`ffmpeg.exe` 随软件分发 | 免去老人电脑手工安装配置；不引入 ffmpeg-python 包装层 |
| 拖拽 | windnd（Windows 原生） | tkinterdnd2 的 PyInstaller 打包需带 Tcl 库，有坑 |
| 文件监控 | 启动扫描 + 拖拽/下载即时入队，不用 watchdog | 低频场景事件驱动无收益，还引入"文件未写完"竞态补丁 |

## 3. 架构

单进程桌面应用，四层：

```
┌───────────────────────── video2mp3 (单进程) ─────────────────────────┐
│  UI 层（Tkinter，适老化大字；主窗口 + 整理U盘二级窗口）                │
│    ↓                                                                  │
│  平台适配层（唯一的 OS 差异点）                                        │
│    Windows: windnd 拖拽 / os.startfile 播放 / psutil+ctypes U盘检测   │
│    macOS:   open 播放 / 文件对话框兜底（开发调试用）                   │
│    ↓                                                                  │
│  服务层（跨平台纯 Python，mac 上可单测）                               │
│    inbox    收件箱扫描、文件稳定校验、去重                             │
│    convert  UUID 生成 → ffmpeg 子进程转换 → 产出校验                   │
│    douyin   剪贴板/输入框链接 → yt-dlp 子进程下载 → 落收件箱           │
│    library  SQLite 映射库读写                                         │
│    export   U 盘检测/扫描/空间预检/复制/读回校验/删除                  │
│    ↓                                                                  │
│  子进程：ffmpeg.exe / yt-dlp.exe（随软件打包，零配置）                 │
└───────────────────────────────────────────────────────────────────────┘
```

转换等耗时操作放后台线程，UI 线程只刷新状态，避免卡死。

## 4. 数据流

入口三选一，统一收敛到收件箱：

1. **拖拽**：视频文件拖入主窗口（windnd）；
2. **收件箱**：微信另存为到 `收件箱\`，软件启动时扫描；
3. **抖音**：粘贴/剪贴板检测到链接 → yt-dlp 下载落收件箱，title 取视频标题。

处理管线：

```
收件箱/原始文件.mp4
  → 等待文件稳定（大小与 mtime 连续两次采样一致）
  → 生成 uuid4().hex，改名移入 video\<uuid>.mp4，SQLite 写入（title=原文件名, status=pending）
  → 后台线程执行：
      ffmpeg.exe -i video\<uuid>.mp4 -vn -ar 44100 -ac 2 -b:a 128k -write_id3v2 0 mp3\<uuid>.mp3
  → 校验：mp3 存在、时长与视频偏差 < 2s → status=done，记录 duration
  → 失败 → status=failed，界面显示 ❌ 与【重试】
```

## 5. 目录结构与数据模型

```
C:\视频管家\
├── 收件箱\            ← 三个入口的落点
├── video\<uuid>.mp4   ← 原视频存档
├── mp3\<uuid>.mp3     ← 转换产物
├── library.db         ← SQLite（WAL 模式）
└── logs\app.log       ← 排错日志（老人无感）
```

```sql
CREATE TABLE videos (
  uuid       TEXT PRIMARY KEY,
  title      TEXT NOT NULL,            -- 界面显示标题
  video_path TEXT,
  mp3_path   TEXT,
  source     TEXT CHECK(source IN ('wechat','douyin','manual')),
  duration   INTEGER,                 -- 秒
  status     TEXT DEFAULT 'pending',   -- pending/converting/done/failed
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  sent_to_usb INTEGER DEFAULT 0        -- 仅历史统计；界面状态以 U 盘实时扫描为准
);
```

## 6. 界面设计

### 主窗口

```
┌──────────────────────────────────────────────────────┐
│  视频管家                                    —— □ ✕  │
│  ┌────────────────────────────────────────┐  ┌────┐ │
│  │  抖音链接粘这里（自动检测剪贴板）        │  │下载│ │
│  └────────────────────────────────────────┘  └────┘ │
│  ────────────────────────────────────────────────────│
│  我的视频                          待传 U 盘：3 个    │
│  ┌──────────────────────────────────────────────────┐│
│  │☐ 一襟风月（5分42秒）✓已在U盘 [▶看] [♪听]        ││
│  │☑ 天仙配选段（3分10秒）        [▶看] [♪听]        ││
│  │☐ 穆桂英挂帅（转换中…）                           ││
│  └──────────────────────────────────────────────────┘│
│  💾 U盘：金士顿 (E:)  剩余 12 GB                     │
│  ┌───────────────────────┐ ┌────────────────────┐    │
│  │ 📤 发送到 U 盘（3 个）  │ │ 🗑 整理 U 盘内容    │    │
│  └───────────────────────┘ └────────────────────┘    │
└──────────────────────────────────────────────────────┘
```

- 字号：正文 18pt / 按钮 22pt / 弹窗 20pt，微软雅黑；白底黑字，操作按钮高对比纯色，状态用图标+文字双重提示。
- 全部操作只有四类：下载、勾选、播放（看/听）、发送；另有二级窗口"整理 U 盘"。无菜单栏、无右键、无设置页。
- **剪贴板自动检测**：后台每 2 秒读剪贴板，发现抖音短链自动填入并提示"已检测到抖音链接，点【下载】"。老人操作路径 = 手机复制 → 切窗口 → 点下载。

### 条目状态与勾选语义

- 列表状态以**当前插入 U 盘的实时扫描结果**为准（盘根目录 `*.mp3` 文件名查 SQLite 匹配），不依赖 `sent_to_usb` 历史字段。
- `✓已在U盘`：默认**不勾**；可手动勾选再发（发送时盘内已有同名文件则跳过）。
- 不在盘内：默认勾选待发。
- 换盘/拔盘自动重扫刷新状态。

### U 盘行为规则

- **自动识别**：每 3 秒轮询可移动磁盘（removable 类型，排除光驱/硬盘分区）。唯一 U 盘 → 自动锁定，界面显示卷标+盘符+剩余空间；多个 → 弹大字选择框；未插 → 显示"请把 U 盘插上"。
- **发送**：勾选项复制到根目录 `\<uuid>.mp3`；发送前 `shutil.disk_usage` 预检空间（按 1.05 倍余量）；目标已存在同名文件 → **跳过不覆盖**（结果提示"已在 U 盘，未重复发送"）；复制后读回比对大小校验；完成后提示"✅ 发送成功，现在可以安全拔出 U 盘了"。
- **重发路径**：整理 U 盘中删除 → 状态自动回到待传 → 再发送。不提供"覆盖"概念。
- **整理 U 盘窗口（二级）**：列出盘内全部 MP3——能匹配库的显示 `标题（时长）`，匹配不上的显示文件名并标注"不是视频管家传的"；勾选后【删除所选】；删除前确认弹窗"确定删除 U 盘里的 N 首歌吗？电脑上的还留着"；删除只动 U 盘文件，完成后刷新主列表状态。

## 7. 错误处理

原则：老人看到人话大字弹窗，完整错误进 `logs/app.log`。

| 故障 | 老人看到的 |
|---|---|
| 抖音下载失败（风控/链接失效） | "这个链接下载失败了。请在手机上把视频保存后，用微信发到电脑上" |
| 转换失败 | "这个视频转换失败了，可以再试一下"——条目保留 ❌ 与【重试】 |
| 磁盘满 | "电脑空间不够了，请联系家人清理" |
| U 盘空间不足 | "U 盘装不下了，请先删掉一些再发" |
| 未知异常 | 大字"出错了，请告诉家人" + 堆栈落日志 |

## 9. 分发

- `uv` 管理开发环境；`pyinstaller` 打 **onedir**（启动快、杀软误报少）。
- `ffmpeg.exe`、`yt-dlp.exe` 放入发行目录，随包分发，老人电脑零配置。
- 桌面快捷方式命名"视频管家"。
- 已知限制：无签名，首次运行需右键"仍要运行"（安装时由家人一次性处理）。

## 10. 与 idea.md 的主要差异

| idea.md 原案 | 本设计 | 原因 |
|---|---|---|
| `b="192k"`，采样率/ID3 未指定 | 44.1kHz/stereo/CBR 128k/无 ID3 | 唱戏机兼容，实测样本对齐；128k 省一半空间 |
| 手工安装 FFmpeg 加入 PATH | ffmpeg.exe 随包分发 | 部署零配置 |
| 本地部署 Douyin_TikTok_Download_API | yt-dlp 子进程 | 服务端项目对单机自用过重 |
| watchdog 监控 + 竞态补丁 | 启动扫描 + 即时入队 + 稳定校验 | 低频场景更可控，失败可见 |
| tkinterdnd2 | windnd | 打包简单、Windows 原生 |
| U 盘 `/音乐/` 子目录 | 根目录 | 唱戏机多不递归子目录 |
| `sent_to_usb` 驱动界面变灰 | U 盘实时扫描驱动状态 | 换盘/盘上删除后状态自动正确 |
| 无 U 盘内容管理 | 整理 U 盘二级窗口（查看/删除） | 用户需求 |
| — | 剪贴板自动检测抖音链接 | 消除"粘贴"这个老人操作难点 |

## 11. 风险与对策

- **yt-dlp 抖音解析失效**：风控更新导致。兜底路径始终可用（手机保存→微信转发→另存/拖拽）；失败提示引导走兜底。
- **ffmpeg 产出与样本规格偏差**：实施第一步用 ffprobe/afinfo 对照实测样本规格，固化参数后再写转换代码。
- **U 盘写入中断**：读回校验 + "可以安全拔出"提示；复制中拔盘提示重发。
- **微信"另存为"是老人最弱环节**：装机时教学一次 + 收件箱桌面快捷方式；拖拽作为替代入口。
- **杀软误报**：onedir 模式 + 如误报则添加信任（家人处理）。
